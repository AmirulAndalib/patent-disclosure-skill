# 对照表总则

## 定位

特征为行、证据为格的底稿。给人传、给人批注的主文件是 `对照表-{场景}-{时间戳}.xlsx`（总览热力 → 对照四列 → 明细全文；无效加路径备忘，FTO 加风险清单，侵权加证据缺口）。不要把整表贴进对话。

## 硬限制

- **禁止**输出无效 / 侵权 / 自由实施 / 可专利性法律结论。备忘只写覆盖情况与待核格。
- **派工**：先 `Read` 对方 `SKILL.md`，再按其流程跑**该包** `tools/`。禁止没读 SKILL 就直接调；禁止调交底包 `cnipa_epub_search.py`。
- 三件套不齐：**只提问**。禁止解读、禁止检索、禁止填格、禁止写 `intake.json`。
- 对照表派工解读时：Obsidian 未就绪则降级 `outputs/patent_reader/`，不要暂停等库路径；默认拆从属权利要求。
- **禁止**无出处格子写成「公开了」。强度「强」必须有可点开的 `source_url` 或段号+摘录。
- 无材料的格子标「无」，摘录留空。
- 全部特征都「强」时在待核清单警告过拟合，不删表。
- FTO / 侵权的「强」行仍须待人审（风险清单标「须人审」；总览该格附同一标记）。
- 默认拆独立权利要求和从属权利要求。
- 右列不够时默认允许补搜；用户已指定全部对照对象则不要再凑数检索。
- 不出 `.docx`，**不出 HTML 工作面**，不要开本机网页表单。
- 材料不够就在对话里按题问；收齐、`INTAKE_OK:1` 之后才分析。不要编。

## 产出

只写 `outputs/patent-chart/{案件}/{会话}/`：`intake.json`（输入归档）、`对照表-{场景}-{时间戳}.xlsx`（主交付）、`chart.json`（机读底稿）。**不要**再写 `chart.md` / `chart.yaml`。不要把 `chart.json` 或摘录全文贴进对话。不同次对照用不同会话目录，不要覆盖上一份。
